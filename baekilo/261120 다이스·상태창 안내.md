# 백일오 · 다이스와 상태창 안내 (261120)

## 1. 다이스 설정

프롬프트 탭에서 '다이스 사용'을 켜고 아래 세 개를 추가한다. 이름은 프롬프트의 `{{dice:이름}}`과 철자가 정확히 같아야 한다.

| 이름 | 표기법 | 쓰는 때 |
|---|---|---|
| action | 1d20 | {{user}}가 위험하거나 결과가 불확실한 행동을 한 턴 |
| clock | 1d6 | `/다음날` 턴 |
| mood | 1d6 | 하루가 시작되는 장면(첫날 제외) |

**action 규칙 칸**
```
쉬움 7, 보통 11, 어려움 15 이상이면 성공. 기준보다 1~5 낮으면 아슬아슬(성공하되 대가), 6 이상 낮으면 실패. 20은 무조건 대성공, 1은 무조건 실패.
```

**clock 규칙 칸**
```
1-2: 결계의 균열 1칸 / 3-4: 세력 간 알력 1칸 / 5-6: 거점의 사고 1칸. /다음날 턴에만 쓴다.
```

**mood 규칙 칸**
```
1: 심통이 나 있다 / 2-5: 평소와 같다 / 6: 이상하게 들러붙는다. 하루가 시작되는 장면에만 쓴다.
```

- 난이도 숫자와 시계 배정은 이 규칙 칸에만 있다. 메인 프롬프트에는 다시 쓰지 않았다.
- 시계 하나가 다 차는 데 보통 12일쯤 걸린다. 더 빠르게 하려면 clock을 1d4로 바꾸고 4를 '두 시계가 1칸씩'으로 정한다.

## 2. 상태창 컴포넌트

- 컴포넌트 칸에 이름 `Seonbongstatus`로 [Seonbongstatus.jsx](Seonbongstatus.jsx)를 통째로 붙여 넣는다. 필요 훅은 useState, useRef, useEffect, 필요 기능은 sendMessage다.
- 디자인 없는 약식이다. 회색 상자에 글자만 나온다.
- **위아래 두 태그(11-24):** 응답 첫 줄 `<Seonbongstatus core="1" …값… />`은 값만 담고 화면에 그리지 않는다. 맨 끝 `<Seonbongstatus view="1" />`이 바로 앞 core의 값을 받아 상태창을 그린다. 답이 길어 끝이 잘려도 값은 위에 남고, 이어쓰기 때는 view 한 줄만 쓰면 된다.
  - 컴포넌트는 각각 따로 된 창(iframe)이라 바깥 창을 거쳐 메시지로 값을 주고받는다(Sbprobe 시험 성공). `window`는 막혀 있고 `globalThis`로만 바깥 창이 보인다.
  - 값 없는 속성은 넘어오지 않는다. `core="1"` · `view="1"`처럼 꼭 값을 붙인다.
  - core도 view도 없는 예전 태그는 예전처럼 그 자리에 그린다(지난 대화 호환).
  - 유저노트에 `[상태창 위]`를 적으면 view가 core 바로 다음 줄에 나와 상태창이 본문 위에 보인다.
- **일상 화면:** 국면, 날짜·시각·장소, 상황 한 줄, 장면 인물과 감정, 백일오의 기분, 판정 결과, 백일오 관계 수치(신뢰·필요·끌림), 신의 탐욕과 거래(값이 있을 때만), 사건 시계 셋.
- **전투 화면(phase가 ph_battle일 때):**
  - 맨 위: 맵 이름, 턴(예: 2/5턴), 레이드 국면, 적의 다음 의도(⚠ 줄).
  - 5×5 맵: 지형 여섯 종을 색과 기호로 칠하고, 장판 칸에는 빨간 빗금, 인물은 점(파랑 {{user}}, 초록 아군, 검정 까마귀 신, 빨강 적)으로 찍는다. 점이나 아래 목록을 누르면 초상화와 상세(생기·오염·상태이상·신기 과열, 적은 체력 칸)가 펼쳐진다.
  - 행동 칸: `이동`을 누르고 칸을 고르면 이동(최대 2칸, 험지 1칸, 둔화면 불가, 컴포넌트가 막아 준다) → 공격/수비/도움 탭 → 행동 → 대상(도움은 아군, 공격은 적이 둘 이상일 때) → 🎲 굴리기 → 한 줄 덧붙이기(비워도 됨) → 보내기.
  - 보내는 글 예: `⚔ 이동 D5 · 공격 · 부적 투척 → 백골설귀 · 🎲9 · 어려움이면 실패 / 보통이면 아슬아슬 · 덧붙임: 노출된 등뼈를 노린다`
  - 판정: 컴포넌트가 1d20을 굴리고, 정해진 난이도와 한 단계 쉬운 난이도의 결과를 함께 보낸다. AI는 덧붙임이 보정할 만한지만 보고 둘 중 하나를 고른다.
  - sendMessage가 없는 환경에서는 보내는 글을 복사하고 "입력창에 붙여넣어 보내세요"라고 알려 준다.
- 화면에 나오지 않는 것: `ties`(NPC 우정). AI만 읽고 이어받는 숨은 값이다.
- **이미지 넣는 곳:** JSX 맨 위의 `SB_MAPS`(맵마다 `img`)와 `SB_PORTRAIT`(인물 코드마다)의 따옴표 안에 이미지 주소를 넣는다. 맵은 1:1 정사각 탑뷰(격자와 점은 JSX가 그린다), 초상화는 정사각. 비워 두면 색과 글자로 대신한다.
- **맵 지형을 고칠 때:** `SB_MAPS`의 칸 배치와 로어북 M1~M4의 '구획'이 같아야 한다. 한쪽을 고치면 다른 쪽도 고친다.

## 3. 유저노트에 적는 것 (전투)

| 적는 것 | 효과 |
|---|---|
| (아무것도 안 적음) | 전투 버튼이 나오고, AI가 {{user}}의 행동까지 서술한다 |
| `[전투직접]` | AI가 {{user}}의 행동과 대사를 대필하지 않고 결과만 서술한다. 버튼은 그대로 나온다 |
| `[전투UI끔]` | 전투 버튼(공격·수비·도움)이 나오지 않는다. 맵과 목록은 나온다 |
| `전투스킬: [공격] 화염부, 결계 찌르기 / [수비] 결계진 / [도움] 정화` | 전투 버튼의 행동 이름으로 쓴다. 안 적으면 AI가 페르소나를 보고 짓는다 |

- 직접 적어서 싸울 때는 `[공격: 화염부] 눈더미를 밟고 뛰어오른다`처럼 보내면 AI가 유니챗 자동 다이스(action)로 판정한다.

## 5. 로어북 키워드가 상태창 글자로 켜지는지 시험

이 봇은 상태창 태그 속 글자로 로어북 문서를 불러오는 구조다. 유니챗 로어북이 AI 응답 속 글자도 읽는지 먼저 확인한다.

1. 로어북에 키워드 `§0`으로 "모든 대사 끝에 '냥'을 붙인다" 같은 티 나는 문서를 하나 만든다.
2. 테스트 채팅에서 첫인사 다음 턴을 받아 본다.
3. 대사 끝에 '냥'이 붙으면 이 구조로 간다. 안 붙으면 다른 방식이 필요하다.
4. 시험이 끝나면 그 문서를 지운다.
