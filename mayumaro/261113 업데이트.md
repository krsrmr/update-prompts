# 1. 끝맺음

**배경**
- 독자 니즈로 드라마의 끝을 "{{user}}의 대답을 기다리는 순간"으로 롤백했더니, "대답을 기다린다"가 본문에 그대로 출력됐다.
- 프롬프트 안의 '기다리'라는 단어를 AI가 베낀다. 그걸 막으려던 진행 줄의 "기다린다는 설명 대신"도 같은 단어를 한 번 더 보여 주는 셈이었다. 그래서 프롬프트에서 '기다리'를 전부 뺐다.
- 동시에 마시로가 혼자 극을 끌고 가지 않게 했다. 원칙은 하나다: **수는 마시로가 두고, 그 수가 어떻게 받아들여지는지는 {{user}}가 정한다.**
    - 마시로 혼자 끝나는 작은 행동(허둥대기, 중얼거림 등)은 끝까지 쓴다.
    - {{user}}에게 닿거나 대답이 필요한 새 수는 내민 데서 멈춘다.
    - 조건을 나열하지 않고, 어느 쪽인지는 AI가 판단하게 한다.
- '새 수'라고 쓴 이유: 취재·NSFW에서 지금 단계는 다 쓰고 다음 단계 문턱에서 멈추는 기존 흐름과 부딪히지 않게 하려고.

## 1-1. `## 무드` › 드라마 › `- 끝:` 줄

**전**
```
  - 끝: 마시로의 말이 끝난 뒤의 침묵, {{user}}의 대답을 기다리는 순간.
```
(11/12 수정본은 "…, 그 침묵에 남은 하나의 이미지." 였다)

**후**
```
  - 끝: 마시로의 말이 끝난 뒤의 침묵에서 멈춘다.
```

## 1-2. `## 진행` › `- 끝은…` 줄 통째로

**전**
```
- 끝은 {{user}}가 반응해야 하는 순간에서 멈춘다. 어디서 멈출지는 무드를 따른다. {{user}}의 대사와 결정은 쓰지 않는다. {{user}}가 맡기면 대신 써도 된다. 멈추는 순간은 기다린다는 설명 대신 장면 속 말·동작·표정으로 보여 준다.
```

**후**
```
- 끝은 {{user}}가 받아칠 수 있는 순간에서 멈춘다. 어디서 멈출지는 무드를 따른다. 마시로 혼자 끝나는 작은 행동은 끝까지 쓴다. {{user}}에게 닿거나 대답이 필요한 새 수는 내민 데서 멈추고, 어떻게 받아들여지는지는 {{user}}가 정한다. {{user}}의 대사와 결정은 쓰지 않는다. {{user}}가 맡기면 대신 써도 된다. 마지막 문단은 장면 속 말·동작·표정으로 끝낸다.
```

**볼 것**
- 끝에 "대답을 기다렸다", "선택은 {{user}}의 몫이었다" 같은 메타 문장이 나오는지.
- 손을 내밀었는데 잡히는 것까지, 부탁했는데 승낙받는 것까지 혼자 써 버리는지.

# 6. LIME 창에 기본 예시만 뜨는 문제

**증상:** 서사 중에 저절로 문자 장면이 되면 LIME 창에 컴포넌트 기본값("아직 안 자요?", "원고 중이라서……")만 뜬다. '수정'을 누르면 서사에 맞는 내용이 보인다. `!메신저`로 부르면 정상이다. (Gemini 4 Argon)

**원인 두 가지**
1. `log` 칸 형식과 예시가 [명령어 !메신저]에만 있다. 이 문서는 키워드 `!메신저`로만 켜진다. 자동으로 문자 장면이 되면 AI는 형식을 모른 채 짐작으로 쓰고, 컴포넌트가 못 읽어서 기본값을 보여 준다.
2. {{user}}의 메시지를 "그대로" 옮기라는 규칙 때문에 큰따옴표(")나 줄바꿈이 `log` 문자열 안에 들어가면 목록 전체가 깨진다.

## 6-1. [명령어 !메신저]

"{{user}}의 입력에서 메시지 내용만 골라…" 줄 통째로:
```
{{user}}의 입력에서 메시지 내용만 골라 log 첫 칸 "u|메시지|日本語|시간"으로 옮긴다. 메시지는 말을 바꾸지 않고 옮기되, 별표 행동 묘사와 큰따옴표(")는 빼고 줄바꿈은 띄어쓰기로 바꾼다. 日本語는 그 말의 자연스러운 일본어 번역(존댓말→丁寧語, 반말→タメ口). !메신저 뒤에 붙은 글이 있으면 그게 첫 메시지다. 메시지 없이 !메신저만 왔으면 마시로가 먼저 보낸다. {{user}}의 다음 메시지는 쓰지 않는다.
```

"log 칸: …" 줄 끝에 이어 붙이기:
```
<LimeChat />은 한 줄로 쓴다. log의 모든 칸에 큰따옴표(")와 줄바꿈을 넣지 않는다(인용은 ‘ ’나 「」).
```

## 6-2. [위젯 규칙] (상시 문서)

첫 줄 교체 (7번 MashiroStash까지 포함한 최종본):
```
Props and content of <MayuPost />, <LunelleEpisode />, <LimeChat />, and <MashiroStash />. When to output them follows the main prompt's Component Output Rules.
```

맨 끝에 추가:
```
[LimeChat]
- LIME mode only. One per reply, after the narration and before the final <MashiroStatus /> or <MashiroMemo />.
- `log`: only what was exchanged in this reply, one item per bubble: "u|{{user}}'s message|日本語|time", "m|日本語|한국어|time" (Mashiro), "st|emoji|sticker name|time", "del|time" (Mashiro unsent), "day|11/9(月)" (only when the date changes). `name`: Mashiro's LIME name (default "真白"). `clock`: time of the last message. `typing={true}`: Mashiro is typing.
- Write the tag on one line. No double quotes (") or line breaks inside any `log` item (quote with ‘ ’ or 「」).
- e.g.
<LimeChat name="真白" clock="00:02" log={["u|메시지|日本語訳|00:00", "m|返信|한국어 번역|00:01", "st|🐰|스티커 이름|00:02"]} typing={false} />
```

예시는 일부러 컴포넌트 기본값과 다르게 했다. "아직 안 자요?"가 뜨면 형식을 못 읽은 것이고, "메시지 / 返信"이 뜨면 예시를 베낀 것이다.

## 6-3. 테스트

- `!메신저` 없이, 연락처를 교환한 기존 채팅에서 둘이 떨어져 있는 시점에 문자 장면을 만든다. 예: `*그날 밤, 침대에 누워 마시로에게 LIME을 보낸다.* "오늘 고마웠어요."`
- 최근에 `!메신저`를 쓰지 않은 채팅이어야 한다(키워드 문서가 켜져 있으면 확인이 안 된다).
- 다시 생성해서 두 번 연속 정상이면 확인 완료. PC에서 곧은 따옴표(")로도 한 번.

# 7. MashiroStash 형식을 [위젯 규칙]으로

마시로가 기구 취재를 제안하면 자동으로 뜨는데, 분류 이름과 예시는 `!리스트`로만 켜지는 문서에 있었다. LIME과 같은 구조라 미리 옮긴다.

[위젯 규칙] 맨 끝에 추가 (첫 줄은 6-2의 최종본):
```
[MashiroStash]
- `items`: one item per string, "이름|분류|개수|상태|메모" (add "|new" at the end for newly added items). 분류: 장난감/구속/코스튬/소모품/마사지/기타. 상태: 미개봉/개봉/취재 사용. 메모: Mashiro's research note, about 30 chars. No double quotes (") or line breaks inside items.
- e.g.
<MashiroStash items={["실크 안대|구속|2|개봉|빛 차단 확인. 시야를 막으면 반응이 커진다고…", "마사지 오일(라벤더)|마사지|2|미개봉|향이 좋다. 손바닥 온도부터 맞출 것"]} />
```

# 8. 세계관 문서 키워드 점검

| 문서 | 문제 | 조치 |
|---|---|---|
| [세계관 달력과 단골 장소] | 키워드가 `!이벤트` 하나뿐. 메인의 "세계관 달력의 가까운 행사와 단골 장소를 핑계와 무대로 쓴다"가 평소엔 작동하지 않는다 | 키워드 추가: 축제, 마츠리, 행사, 데이트, 주말, 휴일, 연휴, 불꽃, 벚꽃, 크리스마스, 할로윈, 생일, 놀러 |
| [마시로의 과거 (비밀)] | 키워드 '비밀', '고백'이 너무 흔해 거의 항상 켜진다. 과거사가 일찍 샐 위험 | 키워드에서 비밀, 고백 삭제 |
| [유카와 홀딩스] | 키워드 '유카와'가 '마츠유카와'에도 걸린다 | 키워드에서 유카와 삭제 (홀딩스·아버지·가족은 유지) |
| [이미지 에셋], [스탠딩 에셋] | 상시도 아니고 키워드도 없어서 절대 켜지지 않는다 | 의도한 거면 그대로 |

나머지(상태창·메모·루넬·SNS 형식은 상시 문서, 노트·비계·포키는 명령어 전용)는 문제없다.
