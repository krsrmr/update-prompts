# 마유마로 11/15 — 사진·통화 기능

동결본(11/13)의 문체·진행 줄은 건드리지 않는다. 메인 프롬프트는 **한 줄 추가**만 한다.

| 기능 | 어떻게 뜨나 | AI가 아나 |
|---|---|---|
| 취소된 셀카 (LIME) | 전송 취소 칸 몇 번에 한 번이 '사진 전송 취소'가 되고, 누르면 셀카가 열린다 | 모름 |
| 비계 사진 | `!비계` 글 하나에 사진. 한 화면 최대 1장, 비계를 두 번 열면 한 번꼴 | `!비계` 턴에만 |
| 통화 화면 | 떨어져서 통화가 시작되는 자리(본문 중간)에 한 번. 음성통화는 세로 휴대폰 화면: 마시로가 걸면 착신 화면이라 유저가 '応答'을 눌러야 연결되고('拒否'를 누르면 울먹임), 유저가 걸면 '呼び出し中…' 뒤 저절로 연결. 영상통화는 기본 그림(장소·옷·표정)이 늘 뜨고, 특별한 상황이면 특별 그림 | 통화가 생겼을 때만 |
| 통화 대사 | 통화 중 수화기 너머 마시로의 말만 말풍선으로. 서술과 그 밖의 대사는 평소 그대로 | 통화 중일 때만 |
| 영상통화 성격 | 마시로는 영상통화를 싫어해서 먼저 걸지 않음 | 성격 한 줄 |

- 통화 NSFW는 막지도, 부추기지도 않는다(아무 말도 쓰지 않음). 지금의 취재 규칙대로 열려 있다.
- 사진이 하나도 없어도 기능은 돌아간다. 셀카·비계 사진은 장수가 0이면 안 뜨고, 영상통화는 그림이 하나도 없을 때만 '카메라 꺼짐'이 뜬다.

## 0. 먼저 음성통화만 넣을 때 (영상통화는 나중에)

컴포넌트는 같은 `MashiroCall`을 쓴다. 봇에게 영상통화 칸을 알려 주지 않으면 늘 음성 화면이 뜬다. 통화 중 마시로의 말은 `CallVoice` 말풍선으로 꾸민다. 2~5장은 건너뛴다.

봇이 늘 읽는 글은 약 600자 늘어난다(상시 글 약 3만 자의 2%쯤). 붙일 곳은 0-1, 0-3, 0-4, 0-7 네 군데.

- 음성통화 화면에 보이는 값은 연결 시각(`clock`)뿐이다. `doing`(하던 일)은 영상통화 특별 그림을 고를 때만 쓰이므로 음성통화 규칙에서는 뺐다.
- **테스트빌드는 본편과 같은 세계관을 쓴다.** 세계관 문서(리마인더·위젯 규칙·습관)를 고치면 본편도 바로 바뀐다. 테스트빌드에서는 메인 프롬프트만 고쳐서 시험한다.

- `CallVoice` ([CallVoice.jsx](CallVoice.jsx))

### 0-2. 화면 시험 (11/15 테스트빌드에서 확인 완료: 본문 중간에 뜸)

본문 가운데에 컴포넌트가 그려지는지 본다. 버리는 대화방에서 봇 응답 하나를 **수정**해 아래를 통째로 붙여 넣고 저장한다.

```
*휴대폰이 짧게 진동했다. 화면에 뜬 이름은 마시로였다.*

<MashiroCall clock="23:41" />

<CallVoice ja="……もしもし。起きてました？" ko="……여보세요. 깨어 계셨어요?" />

*숨을 고르는 소리. 이불이 바스락거리는 소리가 수화기 너머로 작게 섞여 들어왔다.*

<CallVoice ja="べつに用事があるわけじゃないんですけど……その、声、聞きたくなって。" ko="딱히 용건이 있는 건 아닌데요……그, 목소리, 듣고 싶어져서." />
<CallVoice ja="……今の、忘れてください。" ko="……방금 건, 잊어 주세요." />
```

볼 것: ① 통화 화면이 첫 문단 **아래**에 뜨는지 ② 말풍선이 서술 사이사이에 뜨는지 ③ 빈 줄 없이 붙은 마지막 두 말풍선도 둘 다 뜨는지.
**안 뜨면** 0-3 이후를 붙이지 말고 결과를 알려 준다(태그가 글자로 보이는지, 맨 끝 하나만 뜨는지 등).

### 0-3. 메인 프롬프트 `## 출력 형식` (두 버전 모두)

> 11/15 오후: 이 줄과 아래 `me={true}` 줄은 `## Component Output Rules`의 MashiroCall 줄 아래로 옮겼다 → [261115 통화 빈도 조정](261115%20통화%20빈도%20조정.md)

**위치:** `- Manga frames (노트/스케치북): …` 줄 바로 아래, `- Language check: …` 줄 바로 위.
```
- Phone calls: while a call is connected, each line Mashiro says into the phone is one <CallVoice ja="日本語" ko="한국어" /> tag on its own line, instead of the two-line pair. `ja` = Line 1 rules. `ko` = Line 2 rules without ( ), in the same speech style as `ja` (標準語→표준어, 関西弁→사투리). No `"` or line breaks inside. Narration and anything not said into the phone keep the normal format.
```

11/15 테스트: 일본어는 표준어 존댓말인데 한국어 줄이 사투리로 새는 일이 말풍선 6개 중 5개 → 괄호 안 말투 대응을 넣었다.

**(위임 플레이용) 유저 대사도 말풍선으로** — 0-3 줄 바로 아래에 한 줄 더. 유저 쪽은 오른쪽에서 나오는 연두색 말풍선(이름 칸은 YOU). 11/15 테스트빌드에서 시험 중.
```
- If {{user}} has handed their lines to you, {{user}}'s lines into the phone use the same tag with me={true}.
```
- 약 100자. 컴포넌트는 이 줄 없이도 `me={true}`를 알아듣게 만들어 두었다.
- 이 줄이 없으면 위임 때 한 통화 안에서 마시로는 말풍선, 유저는 두 줄 쌍으로 섞인다.
- 주의: 봇에게 '유저 대사를 쓰는 경우'를 한 번 더 말하는 줄이라, 맡기지 않았는데 유저 대사를 쓰는 쪽으로 기울 수 있다. 위임하지 않은 대화에서 봇이 유저 대사를 쓰기 시작하면 이 줄부터 뺀다.

### 0-6. 세계관 문서 [리마인더] — 지금은 넣지 않는다

11/15 테스트빌드에서 이 줄 없이도 둘째·셋째 응답에 말풍선이 이어졌다. 나중에 통화 중 두 줄 쌍으로 돌아가는 일이 생길 때만 넣는다.

**위치:** `직전 응답에 <LimeChat />이 있으면 …` 항목 바로 아래, `대사 견본:` 바로 위에 항목 하나 추가.
```
전화 통화 중이면(직전 응답에 <CallVoice />가 있으면 아직 통화 중) 수화기 너머 마시로의 말은 두 줄 쌍 대신 <CallVoice ja="日本語" ko="한국어" />를 한 줄에 하나씩. 언어 규칙은 대사와 같고 ko엔 괄호·큰따옴표를 쓰지 않음. 어느 쪽이든 끊으면 평소 형식.
```
리마인더 위쪽의 '대사는 두 줄 한 쌍' 줄이 매 턴 반복되기 때문에, 이 예외 줄이 없으면 둘째 턴부터 평소 형식으로 돌아가기 쉽다.

### 0-7. 세계관 문서 [마시로의 배경과 습관] — 선택 (11/15: 넣지 않음)

'먼저 걸지 않음'은 메인 `[성격]`의 연락 줄(0-8)에 이미 있다. 이 줄은 {{user}}가 영상통화를 하자고 할 때 본문(영상)과 화면(음성 카드)이 어긋나는 것만 막는다. 드문 경우라 지금은 넣지 않고, 어긋남이 보이거나 영상통화를 켤 때 4장의 줄로 넣는다.

`[습관과 기호]` 목록 맨 끝에:
```
영상통화를 싫어한다(화면에 얼굴이 크게 나오는 게 부끄럽다). 영상통화를 하자고 하면 카메라를 가리고 목소리로만 받는다.
```

### 0-8. 메인 프롬프트 `[성격]` — 마시로가 먼저 거는 전화 (11/15 시험 중)

> 11/15 오후: `목소리가 듣고 싶을 때도 걺` → `가끔 목소리가 듣고 싶어서도 걺` → [261115 통화 빈도 조정](261115%20통화%20빈도%20조정.md)

동결 원칙대로 한 줄만. 먼저 **테스트빌드 메인 프롬프트에만** 넣어 본다(세계관 문서에 넣으면 본편도 바로 바뀌므로).

**위치:** `[성격]`의 `- 약속 땐 맞선 보듯 … 울먹이며 연락하곤 함.` 줄 바로 아래
```
- 연락: 소심해서 울먹일 때도 대개 LIME 문자. 전화는 문자로는 감당이 안 될 만큼 급할 때만 걺. `phase ≥ 4`면 목소리가 듣고 싶을 때도 걺(걸어 놓고 할 말이 없어 허둥댐). 영상통화는 먼저 걸지 않음.
```
- '울먹일 만큼 급할 때'라고 쓰면 기존 `[성격]`·3단계의 '울먹이며 연락'이 전부 전화로 바뀔 수 있어서, 울먹여도 문자이고 전화는 '문자로 감당이 안 될 때'로 따로 뺐다.
- 우선순위: 문자 > 전화 >>> 영상통화. '대개 문자'와 '…때만'으로 전화가 잦아지지 않게 묶었다. 영상통화는 0-7 습관 줄과 같은 뜻을 한 번 더.
- 지금까지 프롬프트엔 '전화를 건다'는 말이 없어서, 마시로의 먼저 연락은 거의 다 LIME 문자였다.
- '목소리'는 `phase ≥ 4`부터. 기존 4단계 줄의 '이유 없이 보고 싶다는 연락'과 짝이라, 그 전엔 원고 때문에 급할 때만 건다.
- '4단계'라고 쓰지 않은 이유: 상태창에 원고 단계(`stage`: 시나리오·취재·작화…)도 있어서, `[성격]`처럼 `phase` 설명과 떨어진 자리에선 헷갈릴 수 있다. 기존 `## 연재와 금지`의 `phase ≥ 4` 표기에 맞췄다.
- 그래도 잦으면 `목소리가 듣고 싶을 때도`를 `밤에 혼자 있다가 목소리가 듣고 싶을 때도`로 좁힌다.
- **되돌리기:** 이 줄을 지운다.

### 되돌리기

- **통화 대사만 빼기:** 0-3 줄과 0-6 줄을 지우고, 0-4 줄을 아래로 바꾼다(통화 화면만 맨 끝에 뜨고 대사는 평소 형식).
```
- Phone calls while apart: in the reply where the call connects, output <MashiroCall /> once, before the final tag. The call itself is written in the normal format. Props: `clock` = the time it connected.
```
- **통화 전부 빼기:** 0-3, 0-4, 0-6(넣었다면), 0-7 줄을 지운다.
- 0-3은 동결본의 대사 형식에 예외를 다는 줄이다. 붙인 뒤 **통화가 없는 평소 장면**에서 대사 쌍이 그대로인지 2~3턴 확인한다.

**영상통화를 켤 때:** 0-4 줄을 2장의 줄로 바꾸고, [위젯 규칙]에 3장의 첫 줄 교체와 칸을 넣고, 0-7 줄을 4장의 줄로 바꾼다. 0-3·0-6은 그대로 둔다(영상통화 대사도 말풍선).

## 3. 세계관 문서 [위젯 규칙] (상시)

**① 맨 위 첫 줄 교체**

원문:
```
Props and content of <MayuPost />, <LunelleEpisode />, <LimeChat />, and <MashiroStash />. When to output them follows the main prompt's Component Output Rules.
```
교체:
```
Props and content of <MayuPost />, <LunelleEpisode />, <LimeChat />, <MashiroStash />, and <MashiroCall />. When to output them follows the main prompt's Component Output Rules.
```

**② 문서 맨 끝에 추가**
```
[MashiroCall]
- Only in the reply where the call connects. Never output it again while the same call continues.
- `video={true}` only for a video call. Otherwise `{false}`.
- Video call only: `place` = home / school / out (where Mashiro is). `look` = hoodie / dressed (only when out; dressed = his going-out clothes). `face` = fluster / shy / teary / serious / happy (his face when the call connects).
- `doing`: what Mashiro was doing when the call connected, short Korean (예: 침대에서 뒹굴던 중, 원고 작업 중, 막 씻고 나와 머리 말리던 중). `clock`: the time it connected. `name`: his LIME name (default "真白").
- e.g.
<MashiroCall video={true} place="home" face="fluster" doing="침대에서 뒹굴던 중" clock="23:41" />
```

**되돌리기:** ①을 원문으로, ②를 지운다.

## 6. 사진 올리기

상태창 그림과 같은 사이트(`mayumaro.vercel.app`)의 **`img/photo/`** 폴더에 올린다. 상태창 그림이 있는 `img/status/` 옆이다.

| 쓰는 곳 | 파일 이름 | 비율 (권장 크기) | 올린 뒤 할 일 |
|---|---|---|---|
| 취소된 셀카 | `selfie-1.webp`, `selfie-2.webp` … | 3:4 (900×1200) | `LimeChat` 코드 맨 아래 `LC_SELFIE_COUNT = 0`을 올린 장수로 |
| 비계 사진 | `diary-food-1.webp`, `diary-doll-1.webp`, `diary-desk-1.webp`, `diary-outside-1.webp` … | 4:3 (1200×900) | `MayuDiary` 코드 맨 아래 `MD_PHOTO_COUNT`의 종류별 숫자를 장수로 |
| 영상통화 | 아래 두 표 | 9:16 (1080×1920) | 없음. 올리면 바로 뜬다 |

- 장수 숫자는 **실제로 올린 수와 꼭 맞춘다.** 숫자보다 사진이 적으면 빈 칸(회색)이 뜬다. 유니챗은 사진을 못 불러왔는지 알아내는 기능을 보안상 막아 둬서, 코드가 대신 확인할 수 없다.
- 빈도 조절: 셀카는 `LC_SELFIE_EVERY`(기본 4: 전송 취소 4번에 1번꼴), 비계는 `MD_PHOTO_EVERY`(기본 2). 숫자가 클수록 드물다.
- 셀카는 마시로가 보냈다가 부끄러워서 지운 사진이다. 얼굴이 나와도 된다. 비계 사진은 정체를 숨기는 계정이라 얼굴·크로키북·사투리 글씨가 나오지 않게 한다.

### 영상통화 그림

1. **특별 그림** — 마시로가 하던 일(`doing`)에 아래 낱말이 있을 때만
2. **기본 그림** — 장소·옷·표정으로 늘 뜨는 얼굴 그림
3. **카메라 꺼짐** — 그림이 하나도 없을 때의 안전망

### 영상통화 내 화면에 유저 사진 넣기 (선택, 유저가 직접)

`MashiroCall`에는 위젯 규칙에 없는 선택 칸 `you`, `youFace`가 있다. 봇은 평소 이 칸을 모르고, 유저 노트에 적은 유저의 대화에서만 쓰인다.

- 유저가 자기 사진을 표정 단어가 들어간 이름으로 올린다: `me-fluster`, `me-shy`, `me-teary`, `me-serious`, `me-happy` (확장자는 자유). 누구나 열 수 있는 `https://` 주소여야 한다.
- 유저 노트에 붙일 문구 (주소만 자기 것으로):
```
영상통화 화면(<MashiroCall />)에는 you="https://…/me-{face}.webp"와 youFace(이번 내 메시지에서 보이는 내 표정: fluster/shy/teary/serious/happy)를 넣는다.
```
- `{face}` 자리에 표정 단어가 들어가 맞는 사진이 뜬다. 사진이 한 장뿐이면 `{face}` 없이 주소만 적는다.
- 봇이 칸을 빼먹거나 그 표정 사진이 없으면 YOU 상자가 뜬다. 음성통화에서는 쓰이지 않는다.
- 유니챗이 일부 사이트의 이미지를 막을 수 있으니, 처음 한 번은 실제로 뜨는지 확인한다.

## 7. 붙여넣은 뒤 확인할 것

- [ ] **빈도 비교(가장 중요):** 바꾸기 전과 같은 상황을 몇 번씩 돌려서, 마시로가 먼저 연락하는 횟수와 그중 통화 비율을 센다. 추천 상황: 밤으로 건너뛰며 헤어진 날 / 3단계에서 원고가 막힌 날 / 취재 끝나고 헤어진 날. 통화가 문자를 대부분 대신하거나 연락 자체가 잦아지면 0장의 '통화 전부 빼기'로 되돌린다.
- [ ] 마시로가 먼저 영상통화를 걸지 않는지. {{user}}가 영상통화를 걸면 `video={true}`로 뜨는지.
- [ ] (유저 사진을 쓸 때) 유저 노트대로 `you`·`youFace`가 채워지고, 표정에 맞는 사진이 뜨는지.
- [ ] 통화 화면이 연결되는 자리(본문 중간)에 한 번만 뜨고, 다음 응답부터는 다시 뜨지 않는지.
- [ ] 통화 중엔 마시로의 말만 말풍선이고, 같은 말이 두 줄 쌍으로 한 번 더 나오지 않는지. 둘째·셋째 턴에도 말풍선이 이어지는지.
- [ ] 전화를 끊은 뒤, 그리고 통화가 없는 평소 장면에서 대사 두 줄 쌍이 그대로인지.
- [ ] `!비계`에서 사진이 매번이 아니라 가끔 뜨는지(사진을 올린 뒤).
- [ ] LIME 전송 취소 중 가끔 '사진 전송 취소'가 뜨고, 누르면 셀카가 열리고 다시 누르면 닫히는지(사진을 올린 뒤).

## 유저 대사 되풀이 (11/15 반복 확인 → 테스트빌드에서 시험 중)

응답 첫머리에서 {{user}}가 방금 쓴 대사를 *‘야키니쿠.’*처럼 서술 안에 다시 옮겨 적고 반응하는 일이 몇 번 나왔다. 통화가 아닌 장면이라 통화 줄 탓은 아닐 가능성이 높다. 원래 있던 `## 진행`의 "하나하나 받는다"를 봇이 '한 줄씩 다시 꺼내 놓고 반응'으로 처리하는 것으로 보인다.

- 몇 번 더 진행해 봐도 계속 반복됨(11/15). 아래 한 줄을 테스트빌드 메인 프롬프트에 먼저 넣는다.
- 통화 줄 탓인지 확인하려면: 테스트빌드에서 출력 형식의 `Phone calls`·`me={true}` 두 줄을 잠깐 빼고 같은 턴을 3~5번 다시 생성한다.

**위치:** `## 진행`의 `- 반응은 크게, 하나하나 받는다. …` 줄 바로 아래
```
- {{user}}가 쓴 대사와 행동은 본문에 다시 옮겨 적지 않는다(‘ ’ 인용도). 응답은 그것을 받은 마시로의 반응부터 시작한다.
```
**되돌리기:** 이 줄을 지운다.

**한 곳만 넣는다면 이쪽(리마인더)을 권함.** 응답을 어떻게 여는지는 매 턴의 버릇이라, 2만 자 넘는 메인보다 매 턴 맨 아래에서 읽히는 리마인더가 잘 듣는다. 리마인더에 이미 '직전 응답과 같은 표현·엔딩을 쓰지 않음' 같은 매 턴 점검 줄이 있어 결도 맞다.

**리마인더 줄:** 세계관 문서 [리마인더]에 한 줄. 매 턴 맨 아래에서 읽히는 문서라 버릇 고치기엔 더 세다. 본편과 같이 쓰는 문서라 저장하면 양쪽에 바로 적용된다.
위치: `직전 응답과 같은 표현·엔딩을 쓰지 않음.` 항목 바로 아래
```
{{user}}가 쓴 대사·행동을 다시 옮겨 적지 않고(‘ ’ 인용도), 마시로의 반응부터 시작.
```
